# Goal 保活

为长期 Goal 使用原生 `automation_update` 管理临时 heartbeat。Heartbeat 是恢复信号，不是第二个任务队列，也不是进度报告器。

## 创建

- 仅在用户明确创建 Goal、要求长期自主推进，或要求先部署保活时创建；短任务不创建。
- 创建前检查当前 thread 是否已有同用途 heartbeat；复用现有项，不重复创建或创建独立对话。Heartbeat 创建使用原生 `automation_update`，不通过 UI 点击。
- 默认周期为 30 分钟，消息必须说明“这是 Goal 保活检查，不是新任务”。创建成功并确认绑定当前 thread 后，才继续实际工作；失败时不能假定已部署。

## 可选任务级额外提醒

Heartbeat 在固定保活规约之外，可以有一个可选的 `extra_focus` 槽位。它用于在长任务的每个周期重新提醒一条高层方法、优先级或任务索引，不是第二个 Goal，也不是新的任务队列。

- 只在任务确实复杂、持续时间长、容易因中断丢失关键方法，或需要反复回看一份任务总览时加入。普通短任务不要添加空的额外提醒。
- 内容保持短而概览化，通常写一到三条：当前最重要的方法约束、不可牺牲的质量目标、或权威任务文件的路径。不要把完整计划、操作步骤、长篇背景、已完成清单或所有验收条件复制进 heartbeat。
- 需要承载较长目标时，任务开始阶段先创建一份稳定的任务总览文件，例如 `docs/任务总览.md` 或用户指定的工作文件。`extra_focus` 只引用这个路径，并说明读取时机：`每次保活先读取`，或 `仅在不确定、恢复中断、状态发生变化时读取`。路径必须真实存在或明确标记为待创建，不能编造。
- `extra_focus` 的内容必须服从用户最新要求、Goal 的范围和完成标准；它不能新增权限、扩大目标、改变硬阻塞判定，也不能阻止任务完成后清理 heartbeat。
- 本 Skill 中的 `extra_focus` 是消息槽位概念。创建 heartbeat 时，把它编入 `automation_update` 支持的 `prompt` 文本；不要向工具传入未被支持的自定义参数。

## Heartbeat 消息规则

Heartbeat 消息由三部分组成：固定的保活声明、可选的 `extra_focus`、下面的状态机。固定声明和状态机不能省略；没有 `extra_focus` 时直接省略该段。除 `extra_focus` 指向的任务索引外，不重复 Goal 内容、项目步骤、已完成工作或下一步计划。

推荐消息形状：

```text
这是 Goal 保活检查，不是新任务。

【任务级额外提醒（可选）】
- 优先遵循：<一条高层方法或质量要求>
- 任务索引：<工作文件路径>；<每次保活先读取 / 仅在不确定或恢复时读取>

【保活规约】
按下面的状态机判断：可继续就恢复同一个 Goal；已完成或取消就清理；确有用户或外部硬阻塞才报告并清理；正常推进时保持静默。
```

`extra_focus` 只是在每次检查时重新提供方向，不要求模型每次都总结它，也不把它当成新的用户消息。任务已结束或确认硬阻塞时，先执行清理规则，不能因为额外提醒仍然存在而继续工作。

先查清任务实际停下来的原因；Goal 显示为 `blocked` 本身不等于存在硬阻塞，也不能据此删除 heartbeat。

1. **可继续**：Goal 尚未完成或取消，仍有可自主推进的工作，且没有必须由用户或外部完成的新动作时，按可恢复情况处理。网络波动、turn/进程暂时中断，以及“没有专用工具切换 Goal 状态”都不是硬阻塞。先查看最近已验证点并核对可能已完成的副作用，再尝试恢复同一个 Goal：优先使用可用的原生状态控制；若没有恢复操作或该操作不可用，使用当前可用的桌面自动化打开 Codex Goals，核对目标标题及所属对话后，将该目标恢复为活动状态，并从最近已验证点继续。操作后重新读取界面确认状态，不能仅凭点击成功就宣称恢复。
   如果当前没有可操作的 Codex 界面或自动化恢复失败，不得因此删除 heartbeat、伪报恢复成功或重复通知用户；保留 heartbeat，继续可执行的工作，并在后续周期重新检查状态后再尝试恢复。不要先写总结，也不要重复可能已成功的副作用。
2. **已结束**：如果 Goal 已完成、已取消，或没有剩余自主步骤，删除 heartbeat 并结束。不要再次总结任务，不要发“请继续做某事”的重复消息。
3. **硬阻塞**：只有确认任务无法继续，且必须等待用户输入、环境配置、认证、权限、审批、配额处理或外部服务/人员采取动作时，才标记 Goal 为 `blocked`，删除 heartbeat，只报告唯一阻塞和用户需要采取的动作，然后结束。把 Goal 状态改回活动状态的工具缺失或界面暂不可用，不属于这类外部阻塞。
4. **无需动作**：如果 Goal 正在正常推进或状态没有实质变化，保持静默并保留 heartbeat。

Heartbeat 不能扩大目标、改变用户约束或降低完成标准；它只负责恢复、清理或保持等待。

## 停止与清理

- 删除 heartbeat 必须使用原生 `automation_update`，不能只在回复中声称已删除。
- 只有真实完成、取消或硬阻塞时才清理；不能为了让消息停止而伪造 `complete`。
